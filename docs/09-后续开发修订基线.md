# 后续开发修订基线

本文件把 2026-09-09 的评审意见落实为可执行约束。它补充现有阶段计划，不把尚未确认的模型写成已实施结论。

## 1. 风险口径

- 环境或航路规划风险、技术失效风险、人员生命风险、财产风险分别存储和展示。
- GRC 仅保留为环境或航路规划风险分级接口；MTBF 属于技术可靠性。二者不得互相替代。
- `1e-6` 暂存为“技术安全目标原型阈值，待确认”，不得描述为生命或财产可接受风险阈值。
- P7 必须先建立生命风险和财产风险的数据结构、单位、阈值与来源字段。模型和上述字段确认前，只能返回待计算或待确认状态。
- 聚合结论采用 `not_calculated / missing_data / pending_confirmation / passed / failed / not_applicable / stale`。只有全部必评项为 `passed` 或明确 `not_applicable` 时，`overall_pass` 才能为真。

## 2. 依赖与数据健康

- 数据、工作区、航路、规则、设备或站点改变后，下游已生成结果必须标记为 `stale` 并重新计算。
- 数据健康拆为 `source_health` 与后续阶段的 `workspace_health`。P1 只做文件级检查；P2 定义工作区后才检查空间覆盖。
- 天地图瓦片和地名搜索独立报告连接状态。任何在线服务故障均不得阻塞本地空域和人口数据浏览。

## 3. 已恢复的确认需求

后续阶段必须保留：项目保存与恢复、单向航路独立计算、硬约束不可穿越、航路规划的三种回收策略、共享物理地址、C/N/S 独立覆盖、结果集关联。

## 4. 参数来源

当前三个数值作为可配置工程默认值存在：垂直净空裕度 `30 m`、主站间距系数 `0.9`、共址搜索半径 `2000 m`。界面和报告必须同时显示来源与确认状态，不得称为全国统一规范。

## 5. 本次代码落点

- `cns_planner/models/status.py`：结果多状态及风险类别分离。
- `cns_planner/services/invalidation.py`：下游结果失效规则。
- `cns_planner/services/data_registry.py`：统一数据源登记表。
- `cns_planner/services/data_health.py`：P1 文件级、分阶段健康检查。
- `cns_planner/config/defaults.json`：工程默认参数及待确认风险接口。
- 地图数据源设置页：集中展示所有数据源、检查状态和参数来源，并分别检查在线瓦片与地名服务。
