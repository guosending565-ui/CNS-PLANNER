# 交互地图前端交付

2026-09-08。按用户最新要求，优先完成类似原型的交互地图前端，暂缓其他业务算法。

## 实现

- 深青色侧栏、浅色工作区、六步导航、大幅地图、浮动工具和图例。
- Python 调用本机 QGIS 3.44.14，读取用户指定 QGZ：31 个有效本地图层，引用同目录 GeoPackage；使用原始样式渲染。图层名称和定位范围来自项目数据，没有硬编码省份/城市。
- 当前 GeoTIFF：73530 × 45337、1 波段、EPSG:4326、NoData=-99999、像元步长约 0.00083333333 度。默认读取第 1 波段；原始值按人/像元读取，并按像元面积近似换算为人/km²展示。人口渐变不作风险定级，来源部门、时间和单位说明仍需核对。
- 视口范围按需渲染；浏览器拖动时移动已有画面、停止后更新，缩放以鼠标位置为中心。支持按钮缩放、滚轮、双击、区域/坐标定位与全域恢复。
- 设置面板提供本机文件浏览器：盘符、目录、上一级、地址输入、文件类型过滤、选择并确认。也可直接粘贴路径。不是外部上传服务。
- 替换先检查 QGIS 数据引用、有效范围、人口栅格及 CRS；全部有效且配置保存成功后切换。错误保持原地图。来源配置原子写入工程 projects/map_sources.json；原数据文件不写入。

## 技术取舍

新增 map_app.py 启动器 → 已安装 QGIS Python → cns_planner/map_server.py。HTTP 请求由独立线程处理，GIS 操作通过队列交回 Qt 主线程，避免浏览器空闲预连接阻塞服务。浏览器 HTML/CSS/JS 位于 cns_planner/web。无 CDN，无额外 pip 安装。Python 提供数据访问和制图，浏览器脚本负责交互。

独立入口是为了直接读取 QGZ 样式与本地 GIS 数据、获得完整地图布局。已有 app.py 的 Streamlit 元信息能力保留，两入口尚未共享项目。此次不宣称完整规划业务已接入。

## 启动修复（2026-09-08）

检查发现 8765 访问失败、旧版 8501 仍在运行。进一步定位到单线程 HTTPServer 会被浏览器空闲连接阻塞，Windows 端口复用又允许重复实例绑定。已更改为线程化 HTTP 接入 + Qt 主线程 GIS 队列，并开启 Windows 端口独占。

新增“启动地图.cmd”，双击启动后自动打开浏览器；启动器先检查专用健康接口，只在服务就绪后报告成功。重复启动复用实例，失败日志保存到 outputs/map-server.log。app.py 现已统一到地图：直接 Python 运行启动服务，Streamlit 运行自动启动并嵌入地图。旧元信息页面迁至 legacy_app.py。

验证：15 项测试通过，包括保留空闲 TCP 连接时健康检查仍正常、真实地图渲染、重复启动复用、QGIS 缺失提示。Streamlit 新入口自动测试无异常；浏览器实际打开 8501，已确认全国地图正常显示。

默认不请求 QGIS 在线底图；开启时使用项目原有在线图层，需要网络。原始 URL/令牌不发送给前端、不写入应用日志。地图渲染有 25 秒上限；失败提示关闭在线底图重试。在线服务可用性未验收。

当前全图重绘采用视口 PNG，不是全国预生成瓦片。内存最多缓存 8 个视图；窗口输出限制为 2560 × 1800。大区域首次绘制可能需要数秒。本阶段不包含栅格统计、净空、航路/布站计算与正式报告。源数据范围之外空白不代表适飞。
